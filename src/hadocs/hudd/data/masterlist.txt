Research-masterliste / seed inventory
Version: 1.1
Dato: 2026-07-21

===============================================================================
FORMÅL OG VIGTIG AFGRÆNSNING
===============================================================================

Denne tekstfil er en bred research-masterliste til HA-Stability-Knowledge.
Den samler producenter, produktbrands, underbrands, platforme og white-label-
økosystemer, som kan anvendes med Home Assistant via:

- officiel Home Assistant Core-integration
- Works with Home Assistant-certificerede produkter
- Matter
- HomeKit Device
- Zigbee via ZHA eller Zigbee2MQTT
- Z-Wave via Z-Wave JS
- Bluetooth
- MQTT
- ESPHome
- lokal HTTP/API, RTSP, ONVIF, Modbus eller andre åbne protokoller
- autoritative tredjepartsintegrationer
- cloud-integrationer
- custom/HACS-integrationer

Der findes ikke én stabil og komplet liste over “alle producenter, der virker med
Home Assistant”. Home Assistant har over tusind integrationer, og standarder som
Matter, Zigbee, Z-Wave, HomeKit, Bluetooth og MQTT gør, at produkter kan virke uden
en producentspecifik integration.

Kompatibilitet skal derfor altid verificeres for:

- præcis model
- hardware-revision
- region
- firmware
- forbindelsessti
- Home Assistant-version
- integrationens aktuelle dokumentation

===============================================================================
FORBINDELSESTYPE
===============================================================================

LOKAL
Styring og normal drift foregår lokalt mellem Home Assistant og produktet/hubben.
Internet kan stadig være nødvendigt til førstegangsopsætning, konto, firmware eller
fjernadgang.

CLOUD
Normal Home Assistant-styring afhænger af producentens internetbaserede tjeneste.

BEGGE
Der findes både lokal og cloud-baseret funktionalitet, eller forskellige
forbindelsesstier afhænger af model, produktfamilie eller opsætning.

STANDARD
Produktet kan fungere lokalt gennem Matter, Zigbee, Z-Wave, HomeKit Device,
Bluetooth, MQTT, Modbus, ONVIF, RTSP eller en anden standard. Den konkrete model
skal verificeres.

VARIERER
Producenten har flere produktfamilier eller OEM-varianter med forskellig adfærd.

UKENDT
Kræver målrettet research af den konkrete model og integrationsvej.

===============================================================================
SUPPORTKODER
===============================================================================

[HA-CORE]   Officiel integration inkluderet i Home Assistant Core.
[WWHA]      Works with Home Assistant-certificering; verificér præcis model.
[STANDARD]  Understøttes gennem åben eller industristandardiseret protokol.
[UPSTREAM]  Autoritativt eksternt projekt med Home Assistant-relevans.
[CUSTOM]    Typisk HACS/custom integration; ikke officiel Core-support.
[TUYA]      Tuya/Smart Life-baseret eller ofte solgt med Tuya-platform.
[OEM]       White-label/OEM; samme brand kan bruge flere forskellige platforme.
[GROUP]     Koncern eller moderbrand.
[SUBBRAND]  Underbrand, produktbrand eller regionalt brand.
[LEGACY]    Ældre, udfaset eller begrænset integrationsvej.
[CHECK]     Skal verificeres på modelniveau.

SLUTNOTE
===============================================================================

Denne fil skal bruges som researchkø og identitetsregister – ikke som endelig
kompatibilitetsgaranti.

Den officielle Tuya Home Assistant-integration er cloudbaseret og kræver Tuya
Smart eller Smart Life-konto. Direkte Zigbee, Matter, Tasmota, OpenBeken eller
ESPHome kan give en lokal alternativ sti for udvalgte produkter, men det skal
verificeres på præcis model og firmware.

Næste forbedring bør være at konvertere masterlisten til strukturerede records med:
vendor_id, brand_id, parent_group, integration_domain, support_class,
connection_path, local_cloud_class, model_scope, evidence, verified_at og
confidence.
