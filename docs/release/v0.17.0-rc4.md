# HADocs v0.17.0-rc4

HADocs `v0.17.0-rc4` is a prerelease candidate that replaces the unpublished
RC3 candidate. RC3 was not published as a GitHub Release because manual
validation found a release-blocking Windows installer runtime-root defect.

## Windows runtime-root correction

The installed application previously treated its Program Files working
directory as the mutable runtime root. A standard Windows user therefore could
not finish setup or start a scan when HADocs attempted to create configuration
under Program Files.

Installed Windows now stores mutable data under:

```text
%LOCALAPPDATA%\HADocs
```

This includes configuration, output, cache, logs, and relative operational
database paths. Portable Windows continues to use the directory containing its
portable executable. Source checkouts, the Home Assistant App, and containers
retain their existing path contracts.

Application and resource roots are now separate from the mutable data root.
Packaged HASK, HUDD, SQL migrations, schemas, templates, and static files remain
read-only application resources. Relative config, output, cache, log, and
database paths resolve within their approved roots; parent traversal cannot
escape those roots. Explicit absolute and UNC paths remain supported.

## Persistence and migration safety

Configuration publication is atomic and credential-aware:

- the temporary config file is created, flushed, and fsynced before credential
  changes
- publication uses `os.replace` after the file handle is closed
- temporary files are removed on failure
- only credential changes made by the failing operation are rolled back
- existing credentials are preserved across ordinary filesystem failures
- user-visible errors contain neither tokens nor raw exception details

Legacy RC3 and earlier JSON configuration can be copied from the installation
directory on first installed start. Migration never overwrites a destination,
never deletes or moves a legacy file, accepts only valid JSON objects, and is
atomic and idempotent. SQLite and WAL databases are not copied automatically
from old installation directories because their consistency and protected
identity cannot be inferred safely.

## GUI recovery behavior

Setup, Settings, Scan, and Doctor display visible, redacted errors when
configuration cannot be saved or a post-save callback cannot refresh the UI.
The first-run wizard stays open on failure. Scan does not start its worker and
returns to idle when persistence fails.

## Installer and artifact parity

- the Inno wrapper installs `.hadocs-installed` beside the installed executable
- Start menu, desktop, and post-install launch entries use
  `%LOCALAPPDATA%\HADocs` as their working directory
- direct EXE launch uses the same installed-runtime detection contract
- uninstall does not remove user runtime data
- the portable payload never contains the installed-runtime marker
- portable ZIP and installer use one canonical staging payload and matching
  relative SHA-256 manifests
- build commands stop when tests, dependency installation, PyInstaller, or Inno
  Setup fails
- release workflows use read-only repository-content permissions

Windows installers and binaries are unsigned because the repository does not
define an authoritative signing process.

## Included RC3 candidate work

RC4 retains HASK Candidate Readiness, the typed Tuya matcher, immutable HASK
bundle `0.2.1`, and the issue #43 disabled-ZHA scoring correction prepared for
RC3. HASK remains experimental, default-disabled, read-only, redacted, and
analytically isolated from normal findings, Root Causes, recommendations,
severity, device status, and Health Score.

Issue #44 user-configurable ignore rules are not included in RC4.

## Release status

This file prepares RC4; it does not claim that RC4 has been published. The
existing `v0.17.0-rc3` tag remains unchanged, and no stable release is created
as part of RC4 preparation.

## Upgrade validation

Install the RC4 test installer over the accepted pathfix test installation
without uninstalling first. Verify that setup does not return, both Start menu
and direct Program Files executable launches work, existing mutable data remains
under `%LOCALAPPDATA%\HADocs`, and a real Home Assistant scan and all output
surfaces complete successfully. Do not attach credentials, private URLs, or
unredacted installation data to prerelease reports.
