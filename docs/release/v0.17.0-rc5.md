# HADocs v0.17.0-rc5

HADocs `v0.17.0-rc5` is a prerelease candidate that replaces the tagged but
unpublished RC3 and RC4 candidates. This file prepares RC5; it does not claim
that RC5 has been published.

## RC3 Windows runtime-root correction

RC3 was tagged but never published as a GitHub Release. Manual validation found
that a standard Windows user could not finish setup or start a scan because the
installed runtime attempted to write mutable data under Program Files.

Installed Windows now uses `%LOCALAPPDATA%\HADocs` for mutable configuration,
output, cache, logs, and relative operational database paths. Portable Windows
continues to use the directory containing its executable. The read-only
application root is separate from the writable data root, while migration,
atomic configuration saves, and visible secret-safe GUI failure handling make
upgrade and recovery behavior safer.

## RC4 workflow failure

RC4 was also tagged but never published as a GitHub Release. Both tag-triggered
Windows workflows failed with `No module named PyInstaller`: dependencies were
installed into Python 3.11 or 3.12, while the canonical build selected a
separate Python 3.14 interpreter and was invoked with `-SkipDependencies`.
The existing RC4 tag is preserved unchanged and is not reused.

## RC5 reproducible Windows build

- `requirements-build.txt` is the authoritative Windows build-dependency source
  and pins PyInstaller to `6.21.0`.
- The workflows and canonical build script use the same explicit Python 3.14
  executable for pip, pytest, and PyInstaller.
- Dependencies are installed and PyInstaller is verified before staging.
- The build does not depend on global `PATH` or preinstalled local packages.
- Read-only `contents: read` permissions, tag checkout, and canonical payload
  parity between portable and installer artifacts remain enforced.
- No GitHub Release is created automatically.

Windows installers and binaries remain unsigned because the repository does
not define an authoritative signing process.

## Deterministic analysis time

`calculate_integration_health(now=...)` now forwards the same timestamp to
device reachability. Integration freshness and reachability therefore no longer
evaluate one entity against different clocks at the 30-day boundary. The fix
does not change score calibration or filtering, and callers without an explicit
`now` retain the existing wall-clock behavior.

## Continued candidate functionality

RC5 retains HASK Candidate Readiness, the typed Tuya matcher, immutable HASK
bundle `0.2.1`, and the issue #43 disabled-entity correction. HASK remains
experimental, default-disabled, read-only, redacted, and analytically isolated
from normal findings, Root Causes, recommendations, severity, device status,
and Health Score. Issue #44 user-configurable ignore rules are not included.

## Release status

RC3 and RC4 remain unpublished candidates, and their existing tags remain
unchanged. Preparing RC5 does not create a tag, GitHub Release, or stable
release.

## Upgrade validation

Install the RC5 audit-test installer over the installed RC4 audit-test without
uninstalling first. Verify that setup does not return; Start menu and direct
Program Files executable launches work; existing mutable data remains under
`%LOCALAPPDATA%\HADocs`; the database is unchanged by installation; and a real
Home Assistant scan, Dashboard, Explorer, Markdown output, Output Folder,
Doctor, and HASK Preview all work. Confirm `HADocs.exe --version` reports
`0.17.0-rc5`, no `C:\Program Files\HADocs\config` directory appears, and a
forced configuration-save failure is visible, secret-free, and does not start
a scan worker.
