# CA-001 Secret Lifecycle

## Secret definition

The CA-001 secret is exactly 32 octets generated by a cryptographically secure random source. It is installation-local and dedicated to `hask-opaque-reference-hmac-sha256-v1`; reuse for credentials, encryption, signing or another protocol is prohibited.

## Persistent representation

The canonical persisted representation is unpadded Base64url as defined by the URL-safe alphabet:

- exactly 43 ASCII characters;
- alphabet `A-Z a-z 0-9 - _` only;
- no `=` padding or whitespace;
- strict decoding must yield exactly 32 octets;
- decoding followed by canonical unpadded re-encoding must reproduce the stored text exactly.

In-memory HMAC input is the decoded 32 octets, never the 43 text bytes.

## Generation and creation

The producer identity subsystem generates 32 random octets before the first protected reference is collected. Generation must use an operating-system or cryptographic-runtime CSPRNG and must fail rather than substitute timestamps, host data, account data, deterministic seeds or weak randomness.

Creation uses an atomic create-if-absent operation. Concurrent creation attempts must resolve to one durably stored value before collection; first/last-wins replacement after a value is visible is prohibited. Automatic regeneration after prior existence is prohibited.

## Storage assumptions

Storage technology and path are implementation choices, but architecture requires:

- durable local storage outside source, bundle, output and cache directories;
- least-privilege access restricted to the producer identity subsystem and necessary backup agent;
- atomic replacement for an authorized rotation;
- no inclusion in public diagnostics, crash reports, telemetry, logs or snapshots;
- no environment-derived host, account or machine identifier as secret content.

## Startup validation

Before any protected-reference collection, read the canonical text, verify alphabet/length/padding, decode strictly, verify 32-octet length and verify canonical re-encoding. Do not log the text, decoded bytes, partial value or digest of the secret.

Missing, unreadable, malformed, non-canonical or wrong-length values produce `secret_unavailable` within the future internal error vocabulary. No protected references or dependent current snapshot are activated. A last valid immutable snapshot may remain explicitly stale.

## Backup, restore and migration

Backup intended to preserve the same installation privacy context must include the secret as protected sensitive material. Backup encryption/access controls are operational requirements; CA-001 does not define their implementation.

Restore or approved host migration preserves the exact 32 octets when continuity is required. Copying the secret causes the copied environment to derive identical references; classification of a copy as migration or clone is outside CA-001 and remains blocked AI-002 work.

## Rotation

Authorized rotation is explicit and audited. Permitted triggers are:

- confirmed or reasonably suspected secret disclosure;
- cryptographic-format migration requiring a new secret by a later approved architecture;
- an externally approved installation-separation decision.

Restart, update, configuration reload, transient read failure, hostname/address change and ordinary restore are prohibited automatic rotation triggers.

Rotation generates a fresh independent 32-octet secret and changes every derived reference. It must occur at an atomic snapshot boundary: old and new references are never mixed in one current snapshot. Dependent observations and relationships are regenerated consistently. Rotation cannot silently relabel a prior public identity as continuous.

## Loss, corruption and recovery

Secret loss or corruption cannot be repaired by guessing or silent regeneration. Recovery must restore the exact validated secret from an authorized backup to preserve identity. If exact recovery is impossible, collection remains failed closed until a separately authorized identity-reset/rotation action accepts full reference regeneration and historical discontinuity.

Secret material is never displayed for troubleshooting. Diagnostics expose only bounded status and safe error code.
