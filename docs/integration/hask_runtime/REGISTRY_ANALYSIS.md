# Registry Analysis

The officially documented display-entity command is suitable for enabled display inventory, not complete registry integrity because disabled entries are excluded and fields are compact/conditional.

Full entity, device, and area registry list commands appear in an official custom-dashboard example, but response wire schemas are not documented there. Their live structures are therefore version-tagged context, not a compatibility contract.

Safe opportunities include orphan/reference checks, uniqueness checks, entity-device-area consistency, target resolution, and disabled/hidden context. Unsafe conclusions include treating a missing entity as device failure or a registry relationship as runtime connectivity.

Floor and label list commands were observed live but not independently documented; they remain `OBSERVED_UNDOCUMENTED`.
